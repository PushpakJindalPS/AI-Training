Microsoft Copilot Studio:
Build Your Own AI Agent

No code required · ~45 minutes

Copilot is Microsoft's AI assistant. Copilot Studio is the platform that lets you build your own — connected to your data, your systems, and your workflows.
Set the scene: everyone in this room has probably used Microsoft Copilot by now. Copilot Studio takes the next step — instead of using a pre-built assistant, you design one. You decide what it knows, what it can do, and who it talks to. No developer required.

Microsoft Copilot vs Copilot Studio

Two different things — easy to confuse

Microsoft Copilot

The AI assistant built into Microsoft 365

Pre-built by Microsoft — summarises emails, drafts documents, answers questions about your files

You use it. You can't change its core behaviour.

Included in M365 Copilot licence

Copilot Studio

The platform for building your own copilot

You design the agent — what it knows, how it responds, what actions it can take

Connect it to your own documents, SharePoint sites, APIs, and Power Automate flows

Separate licence (Power Platform)

Analogy: Microsoft Copilot is like hiring a ready-made assistant. Copilot Studio is the job spec, onboarding pack, and training process — you build the assistant from scratch, exactly the way you want.
This distinction matters because participants often conflate the two. Copilot (the assistant) is consumption. Copilot Studio is creation. The rest of this session is about creation.

Three building blocks — everything else is detail

🗣️

Topics

Conversation flows — what the agent says in response to specific questions or triggers. You define: when this is asked → respond with this.

Think: decision tree + scripted responses

📚

Knowledge

Documents, SharePoint sites, or URLs your agent can search and cite. This is the RAG layer — the agent reads your content to answer questions.

Think: your agent's library

⚡

Actions

Connections to external systems — run a Power Automate flow, call an API, retrieve data from Dataverse. This is what makes the agent do things, not just say things.

Think: your agent's hands

A simple agent might only use Knowledge. A powerful agent combines all three — Topics to guide the conversation, Knowledge to answer questions, and Actions to take next steps.
Keep this slide crisp. The three building blocks are all they need to understand before building. The analogy: Topics is the script, Knowledge is the library, Actions is the toolbox. Everything in Copilot Studio maps to one of these three.

Topics — Guiding the conversation

What a Topic contains

Trigger phrases

The questions or phrases that activate this topic — "How do I submit a leave request?" · "What are the holiday dates?"

Conversation nodes

Send a message · Ask a question · Branch based on answer · Call an action · End the conversation

Variables

Store user input (e.g. name, date, department) and use it later in the conversation or action

Example conversation flow

User
How do I book a meeting room?
Copilot (Topic triggered)
I can help you with that. Which office are you in?
Dubai
For the Dubai office, rooms are booked through Outlook. Here's the booking link: [link]. Would you like me to open your calendar?
Topics give you precise control over specific interactions. The system prompt approach from GPT and Claude is "give me character and I'll figure it out" — Topics are the opposite: "I'll tell you exactly what to say in this situation." Most enterprise agents use a mix of both: Topics for controlled processes, generative AI for open-ended questions.

Knowledge — Connecting your agent to your content

This is the RAG layer — your agent searches your documents and cites the source

Source type

SharePoint sites

Point to a SharePoint site or document library — the agent indexes it and can answer questions from any document it contains

Source type

Uploaded files

Upload PDFs, Word docs, or spreadsheets directly — useful for policies, SOPs, product catalogues

Source type

Public websites

Add a URL and Copilot Studio crawls it — useful for FAQ pages, public documentation, product sites

What the user sees: A direct answer with a "Source:" citation linking to the original document — they can verify the answer themselves.
Key constraint: The agent only reads documents the logged-in user already has permission to access. SharePoint permissions apply — no data leakage between users.
Knowledge is the fastest way to add value. Point a Copilot Studio agent at an HR policy SharePoint site and you've instantly created an HR FAQ bot — no manual scripting required. The permission inheritance is critical for enterprise adoption: it's a feature, not a limitation.

Actions — Giving your agent the ability to do things

Knowledge makes the agent say things. Actions make it do things.

Action type

Power Automate flows

Trigger any Power Automate flow directly from the conversation — submit a form, create a Planner task, send an email, update a SharePoint list

Action type

HTTP requests / connectors

Call any REST API — internal systems, Dataverse tables, third-party services with connectors (Salesforce, ServiceNow, Jira)

Action type

Dataverse queries

Read and write to Dataverse tables — employee records, project data, support tickets, approval statuses

Action type

Pre-built connectors

700+ Power Platform connectors available out of the box — no custom development needed for common systems

Example: User asks "Can you raise a support ticket for the printer issue on floor 3?" — the agent collects the details via Topics, then fires a Power Automate flow that creates the ticket in ServiceNow. The user never leaves the Teams chat.
Actions are what separate a chatbot from an agent. Without actions, the agent can only answer questions. With actions, it can take next steps on behalf of the user. The Power Automate integration is particularly powerful because most enterprises already have PA flows running — Copilot Studio can surface them through conversation.

Generative AI Mode — The most powerful setting

Without it, the agent only answers questions you've explicitly scripted. With it, it can answer anything within its Knowledge sources.

Classic mode (Topics only)

Fully scripted

Every question must match a Topic or trigger phrase

Precise control — but high maintenance; you must anticipate every question

User asks an unscripted question → "I didn't understand that"

Generative AI mode (recommended)

LLM-powered responses

Agent uses GPT-4 to answer any question by searching Knowledge sources

Unrecognised questions get a generative answer — grounded in your documents

Topics still override for controlled processes

Generative Answers

LLM synthesises an answer from Knowledge sources — cites the document

Generative Actions

Agent decides which Action to call based on what the user is asking — no explicit routing needed

Orchestration layer

Agent reasons about whether to use a Topic, a Knowledge source, or an Action — in real time

Generative AI mode is where Copilot Studio becomes genuinely powerful. Classic Topics are still useful for regulated, compliance-sensitive processes where you need exact wording — legal disclaimers, HR procedures, safety instructions. Everything else benefits from generative mode.

Teams deployment tip: "Add to Teams" creates a personal app visible to all users in your tenant — no IT deployment request needed. Admins can pin it to the Teams sidebar for everyone.
Analytics built in: Copilot Studio shows you conversation volume, escalation rates, and which topics are triggering most — you can see exactly where users are getting stuck.
The Teams deployment is by far the most common for enterprise use. The key message: you build it once in Copilot Studio, and any deployment is just enabling a channel toggle — no additional development work.

Activity — Design your own Copilot

Design brief — answer these five questions

1. Who is the user?

Who will talk to this copilot day-to-day?

2. What problem does it solve?

What questions does it answer or tasks does it automate?

3. What Knowledge does it need?

Which SharePoint sites, documents, or data sources would you point it at?

4. Does it need Actions?

Should it create records, send notifications, or trigger flows — or just answer questions?

5. Where does it live?

Teams, SharePoint, a website, or somewhere else?

Starter ideas

HR Policy Bot

Answers questions from the employee handbook and HR policy documents on SharePoint

Project Status Agent

Queries Dataverse or a SharePoint list for project updates — gives stakeholders instant status without a meeting

IT Helpdesk Agent

Answers common IT questions from the knowledge base; raises a ServiceNow ticket via Action if unresolved

Document Q&A

Load a set of contracts, proposals, or reports — let the team query them in plain language

Debrief question: "What's the first thing you'd connect it to — a Knowledge source or an Action? Why?"
Give participants 10 minutes to fill in the five questions individually. Debrief by asking 2–3 people to share their use case and their Knowledge source choice. The insight to draw out: most enterprise value comes from Knowledge (reading existing documents) before Actions (doing new things).

Key Takeaways

1
Copilot Studio ≠ Microsoft Copilot — one is a ready-made assistant you use; the other is a platform where you build your own
2
Three building blocks: Topics (conversation scripts), Knowledge (document search), Actions (doing things)
3
The fastest path to value is Knowledge + Generative AI mode — point it at SharePoint and your documents become instantly queryable
4
Permissions are inherited from SharePoint — users only see what they already have access to. Security is built in, not bolted on.
5
Actions connect it to systems — Power Automate flows, APIs, Dataverse. This is what makes it an agent, not just a chatbot.
6
Deploy once, run everywhere — Teams is the default starting point for enterprise deployment; no IT project required
7
Use Topics for controlled processes (compliance, HR, safety), Generative mode for everything else
Close by asking: "If you could build one agent that would save your team the most time — what would it be?" Their answer is their next project. Copilot Studio is the platform to build it.
